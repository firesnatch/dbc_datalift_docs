SQL capability

What PostgreSQL adds beyond DB/C FS.

DB/C FS is limited to a narrow subset of SQL. DBC DataLift runs on PostgreSQL, giving customers access to a far richer query model for reporting, integrations, and analytics.

  • Window functions such as ROW_NUMBER(), RANK(), and aggregate over partitions
  • Common table expressions (CTEs) for readable multi-step queries and recursive logic
  • Correlated subqueries and nested query patterns used in enterprise reporting
  • CASE expressions and conditional logic for transformation and classification
  • Analytic functions and advanced aggregations for modern business reporting
  • JSON functions and PostgreSQL-native data shaping for Python, APIs, and integration workflows
  • Advanced planner visibility with EXPLAIN to understand index usage and optimization decisions
  • Standard PostgreSQL tooling and ecosystem compatibility across BI, ETL, scripting, and reporting tools

Query Transparency

Real execution plans show exactly which indexes are being used.

DB/C FS offers very little insight into how queries are being resolved. DBC DataLift is built for query visibility using PostgreSQL planning and the EXPLAIN statement.

Example query: a join between im_0001 and pm_0001 with indexed access on both tables.

EXPLAIN (FORMAT JSON, VERBOSE, COSTS OFF)
SELECT i.reference, p.product
FROM im_0001 i
JOIN pm_0001 p ON i.product = p.product
WHERE i.source = 'PO'
  AND i.reference = '00001WW3'
  AND p.description = 'BANANAS'
  AND p.product = 'BANANA-001';

Foreign Scan: im_0001
DBC Access: index_prefix
DBC Index: KEY1 (source, reference, line_number)
DBC Key Prefix Count: 2

Foreign Scan: pm_0001
DBC Access: index_full_key
DBC Index: KEY4 (description, product)
DBC Key Prefix Count: 2

This gives operators and developers a real, explainable path to performance tuning that DB/C FS simply does not provide.

Data File Maintenance

Customers should not be forced into brittle, manual steps.

  • DB/C FS requires Database Definition File generation when data files expand. Missing the step can push access offline.
  • DBC DataLift reads and uses .DEF files more dynamically and can detect/act on structure changes.
  • This reduces operator burden and decreases the chance of a silent disruption.
  • It is a better fit for environments where files change over time and need easy maintenance.
